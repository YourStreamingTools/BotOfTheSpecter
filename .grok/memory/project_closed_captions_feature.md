Closed Captions is a feature built across 2026-06 (**SHIPPED** — committed in the 2026-06/07 batch; all the "(built …, uncommitted)" notes below are now committed). Free, in-house, **no API key, no cost** — all STT/detection runs in the streamer's browser.

**Files:** `dashboard/closed-captions.php` (captioner: Start/Stop + settings), `overlay/closed-captions.php` (display-only OBS overlay), `overlay/index.css` (`closed-captions-overlay-page-*` styles), `dashboard/css/dashboard.css` (`.cc-url-card`/`.cc-sound-status` + page styles), schema in `dashboard/includes/usr_database.php` (`closed_captions_settings` table), `dashboard/lang/{en,de,fr}.php`, plus `dashboard/menu.php` + `dashboard/overlays.php` registration. POC scratch file: `dashboard/closed-captions-poc.php`.

**STT:** `webkitSpeechRecognition` (Web Speech API) — **Chrome/Edge only**. `continuous`+`interimResults`. `recognition.lang` read ONLY at `start()` (changing language must RESTART recognition). `lang` controls output spelling (en-AU → "colour"). No auto-punctuation → a `punctuateFinal()` helper capitalizes + adds terminal `.`/`?`. Default TTS-style volume rules don't apply (display-only).

**Transport (KEY):** captioner does `socket.emit('CLOSED_CAPTION', {code, text, isFinal, action})` → relayed to same-code overlay clients by an **explicit** server handler (`handle_closed_caption` / `handle_closed_caption_clear` in `websocket/server.py`, registered in `setup_event_handlers()`). The wildcard does NOT relay client-emitted events to same-code clients — see [[websocket-wildcard-is-intentional]]. **Any server.py change needs a websocket-server restart.** The base CC relay handlers were added this session, so deploying CC the first time DOES require a WS restart; the action-tags add-on below does NOT touch server.py.

**Overlay:** display-only, `?code=API_KEY` auth, Socket.io to `wss://websocket.botofthespecter.com`. `renderBand()` keeps committed + interim ≤ `maxLines` (interim counts as a slot). On faded-out band, stale lines are cleared so the prior sentence doesn't flash back on resume. Settings JSON endpoint returns 9 fields — deliberately NOT `action_tags_enabled` (overlay renders action tags purely from the per-caption `action` flag, staying stateless).

**Sound-action tags (YAMNet):** opt-in `action_tags_enabled` toggle (TINYINT default **0/OFF**). When on + captioner started, lazy-loads TF.js + YAMNet (`tf.loadGraphModel(tfhub yamnet/tfjs/1, {fromTFHub:true})`), captures mic via an **AudioWorklet** (Blob-URL processor, 16kHz mono, separate getUserMedia stream running concurrently with the recognizer — proven OK in Chrome/Edge), infers every 500ms on 0.96s (15360-sample) frames, `scores.mean(0)`, threshold 0.4, 1200ms per-tag debounce. Target class indices → tags: 13→`[LAUGHING]`, 42→`[COUGH]`, 44→`[SNEEZE]`, 62→`[APPLAUSE]`. Emits as a normal `CLOSED_CAPTION` with `action:true`; overlay styles it `--action` (italic, opacity .75). Tensors disposed every inference (manual, tf.tidy can't span async). Zero cost when toggle off (no static tfjs tag; CDN load is dynamic + gated).

**Corrections/glossary dictionary (built 2026-06-06, uncommitted):** per-user `closed_captions_corrections` list table (`match_text, replace_text, match_mode ENUM('word','substring'), case_sensitive, enabled, sort_order`) in usr_database.php `$tables` (NO default-row — it's a list table). Editor card on the captioner page; CRUD via a separate `$_POST['cc_corrections_save']` JSON endpoint (replace-all: DELETE then prepared INSERT, bind `"sssiii"`). `applyCorrections(text)` (in-page JS) builds ≤2 cached alternation regexes (case-insensitive `gi` + case-sensitive `g`), regex-escaped, `\b`-wrapped for word mode, longest-first; forces canonical casing via stored `replace_text`. Wired in `r.onresult` **FINAL branch only** (after `punctuateFinal`, before emit) — never interim, never action tags.

**Live translation (built 2026-06-06, uncommitted):** browser built-in on-device **Translator API** (`window.Translator`, Chrome 138+/Edge 148+, free, no key, on-device, offline after one-time language-pack download). `target_language VARCHAR(10) DEFAULT ''` added to `closed_captions_settings` (''=off/same-as-spoken). Dashboard splits **Spoken language** (drives `recognition.lang`) from **Caption language** (translate target, full short-code set). `liveTranslator` singleton: maps region→short code (`de-DE`→`de`), gated on target!=source, `availability()`→`create({monitor})`→`translate()`, destroyed on stop/change. Translates the **CORRECTED final** text via a serialized `translateChain` Promise (preserves order) before emit; preview shows corrected source. Graceful fallback to untranslated + one-time notice if unsupported/unavailable/throws. **Overlay + server.py UNCHANGED** (text arrives already corrected+translated). Order: punctuate→correct→translate→emit. Corrections double as the do-not-translate source-cleanup. Desktop Chrome/Edge only (same as STT); first-use pack download gated on ~22GB disk + GPU>4GB VRAM or 16GB RAM.

**Firefox support (researched 2026-06-07, decision = info only, NOT built):** the overlay AND the YAMNet sound action-tags already work in Firefox (HTML/WebSocket; getUserMedia+AudioWorklet+TF.js are all stable in FF). Only the captioner's STT + translation are Chromium-only and block Firefox. Firefox 142/143 DID ship an on-device whisper.cpp `SpeechRecognition` but behind the `media.webspeech.recognition.enable` about:config pref (off by default, no ship date, no Android) — not user-reliable, don't depend on it. Firefox filed a NEGATIVE standards position on the web Translator API and its Bergamot page-translation is browser-UI-only (not callable from page JS). To make the captioner truly cross-browser you'd swap Web Speech→Transformers.js Whisper (tiny/base) and Translator API→Transformers.js Opus-MT (per-direction models): cross-browser + on-device but ~1–3 days, big model downloads, chunked re-transcribe UX (whole-phrase rewrites, ~0.5–2s lag, worse on FF/Linux which lacks WebGPU). The existing 48k→16k capture AudioWorklet is reusable for Whisper mic capture. Recommended (deferred): keep native Web Speech default on Chromium, offer the Transformers.js path as an opt-in "experimental cross-browser captions" only if Firefox demand appears. The captioner already detects missing `SpeechRecognition` and shows an unsupported state.

**Live settings push (built 2026-06-07, uncommitted):** changing appearance settings (font size, colour, position, background) on the dashboard did NOT update the overlay live — the overlay only read settings on its own load, so in OBS nothing changed until the browser source was refreshed (perceived as "font size only changes at the extremes / no in-between"). Fix mirrors the CLOSED_CAPTION relay: dashboard emits `CLOSED_CAPTION_SETTINGS {code}` on save success → new explicit `handle_closed_caption_settings` in server.py (`broadcast_event_with_globals(..., code=get_code_by_sid(sid), source_sid=sid)`, registered in setup_event_handlers) → overlay `socket.on('CLOSED_CAPTION_SETTINGS', loadSettings)`. **Needs a WS server restart.** GOTCHA: the overlay's pre-existing `SPECTER_SETTINGS_UPDATE` listener was DEAD for captions — that event's server handler routes via `broadcast_to_timer_clients_only` (filters to clients with `'timer'` in the name = Working/Study overlay), and the CC overlay registers as name `'Closed Captions'`, so it never received it. Don't reuse SPECTER_SETTINGS_UPDATE for non-timer overlays. (Overlay font sizing itself is correct: px→vh `fontSize/1080*100`, linear, no clamp.)

**Font selector (built 2026-06-13, uncommitted):** caption typeface is now user-selectable. Added `font_family VARCHAR(50) NOT NULL DEFAULT 'Inter'` to `closed_captions_settings` (auto-migrates via usr_database.php's generic column-add). Curated Google-Fonts list `['Inter','Roboto','Open Sans','Lato','Montserrat','Poppins','Oswald','Raleway','Ubuntu','Nunito']` is declared in THREE places that MUST stay in sync: `$allowedFonts` in dashboard/closed-captions.php, `$allowedFonts` in overlay/closed-captions.php, and `allowedFonts` in the overlay JS. Dashboard has a `<select name="font_family">`. Overlay loads the chosen font two ways: a server-rendered `<head>` Google-Fonts `<link>` for the initial paint (no flash) + a JS `ensureFontLoaded()` lazy-loader (seeded with `overlayInitialFont` so it doesn't double-load) for live switching. Band CSS = `font-family: var(--cc-font-family, "Inter"), "Segoe UI", system-ui, sans-serif` (root default `--cc-font-family:"Inter"`; status pill + error screen stay plain Inter). Live-switch rides the EXISTING `CLOSED_CAPTION_SETTINGS` push — **no server.py change, no WS restart for this add-on**. Resilience: both dashboard AND overlay SELECTs fall back to a font_family-less query if the column doesn't exist yet (dashboard runs the migration only in layout.php at page END, after its top-of-page SELECT; the overlay never runs the migration) — prevents a first-load blank-to-defaults that could overwrite real saved settings on Save.

**Gotcha (recurring):** the `cc_save` handler's `bind_param` must stay count-matched — now `"isisssiiiiss"` (12) for 12 placeholders / 12 vars (11th = `target_language`, 12th = `font_family`). A mismatch = HTTP 500 (happened twice). Recount whenever a settings column is added. (The separate `cc_corrections_save` handler binds `"sssiii"` = 6.)

**Gotcha (dual-mic contention, fixed 2026-06-05):** webkitSpeechRecognition and the YAMNet detector are two consumers of the SAME physical mic (Web Speech owns its own capture — you can't hand it a MediaStream). In Chromium the device's APM (AEC/NS/AGC) config and sample rate are negotiated ONCE per shared device, so a detector stream that (a) forces `AudioContext({sampleRate:16000})` or (b) requests `echoCancellation:true` makes Chrome re-open/reconfigure the device mid-session → the recognizer **drops words**. Fix shipped: detector uses a native-rate `AudioContext` (no forced rate) + a fully RAW tap (`echoCancellation/noiseSuppression/autoGainControl:false`) + resamples 48k→16k inside the AudioWorklet (linear interp, `sampleRate` worklet global, `${TARGET_SR}` injected into the Blob source) + pins `deviceId:{exact}` to the same mic the recognizer's permission-prompt stream locked onto (captured via `getAudioTracks()[0].getSettings().deviceId`, passed to `soundDetector.start(deviceId)`). RAW audio is also BETTER for sound-event classification. TF.js main-thread jank was NOT the cause (code already uses async `.data()`, warmup, `inferBusy` guard, dispose; decoder runs out-of-process). Don't re-introduce a forced 16k context or AEC on the detector tap.
