**Word Replacer** module (**SHIPPED**; built 2026-06-30, committed "Add word replacer module" `da302bb1` + "Add dedicated Word Replacer module tab" `511721a8`), inspired by a now-defunct standalone echo bot. Bot occasionally re-posts a viewer's chat line with random syllables swapped for a streamer-set word (default `fun` — user changed it from the draft's `butt` on 2026-06-30). The user demanded ALL "butt"/that-bot branding be scrubbed everywhere (code, docs, AND the plan): default→`fun`; every `butt`-flavored code identifier renamed to `word_replace_*` (`buttify`→`word_replace_transform`, `is_buttable_message`→`word_replace_is_transformable`, `_ButtifiedContent`/`_ContentItem`→`_WordReplaceContent`/`_WordReplaceItem`, `.buttify()`→`.transform()`, `buttified`→`did_replace`); no brand name in comments. If you ever reintroduce the inspiration's name, expect pushback. Plan: `.grok/plans/2026-06-30-word-replacing-feature.md`.

**Why:** fun engagement module, fully separate from `blocked_terms` moderation; off by default; **beta bots only**. There is NO manual chat trigger — the random auto-echo is the only mechanism and it's controlled entirely from the dashboard (user decision 2026-06-30: removed the `!buttify`/`!butt` commands that the first draft had).

**How to apply / gotchas:**
- ALL the code (algorithm + DB cache + opt-out + echo) is **inlined as module-level functions in EACH bot file** (beta.py AND beta-v6.py, own copy each), placed at the top of the "# Functions for all the commands" section just before the known-bots registry. NO separate `word_replace*.py` modules — the user rejected that split (2026-06-30): bot files are self-contained monoliths ([[feedback_bot_file_function_placement]]). Runtime funcs use module globals directly (`mysql_connection`, `chat_logger`, `send_chat_message`, `CHANNEL_NAME`, `BOT_USERNAME`, `MAX_CHAT_MESSAGE_LENGTH`); guarded `import pyphen` is at the top of the block; cache globals `_word_replace_cache`/`_word_replace_cache_time`/`_last_word_replace_echo` are per-process (fine — one process = one channel). entry points: `load_word_replace_settings(force=)`, `word_replace_maybe_echo(author, content, is_echo=)` (hook via safe_create_task/create_task), `word_replace_user_opt_out(username, opt_out)`.
- **pyphen gotcha (was a real bug):** `Pyphen.iterate()` yields `(head, tail)` TUPLES, not syllables → crashes on every multi-syllable word once pyphen is installed (it is, via requirements.txt). Use `Pyphen.inserted(word).split('-')` for syllable chunks. Vowel-cluster regex is the no-pyphen fallback.
- Only chat commands are `wordreplaceoff`/`wordreplaceon` — always-on viewer opt-out, NOT in `builtin_commands` (not disableable; don't add to builtin set or builtin_commands.json). NO `!buttify`/`!butt` (removed; dashboard-only control). `word_replace_send_echo`/`word_replace_cooldown_ready` are internal module-level helpers (called only by `word_replace_maybe_echo`).
- All bot command methods take `self` in BOTH beta.py (TwitchIO 2.10) and beta-v6.py (TwitchIO 3.x, AutoBot subclass). The many no-`self` commands in beta-v6.py are a SEPARATE pre-existing port bug (mis-binds args) — unrelated to this feature.
- Schema in `dashboard/includes/usr_database.php` ([[project_per_user_schema]]): `word_replace_*` cols on `protection` + tables `word_replace_ignored_users` / `word_replace_ignored_words`. UI is its OWN `word-replacer` tab in `modules.php` (nav `<li data-tab="word-replacer">` + `<div class="tab-content" id="word-replacer">` + `modules_tab_word_replacer` lang key ×3 — user wanted a tab, not a section buried under Chat Protection); CRUD in `api/module_data_post.php` (its 5 branches redirect `?tab=word-replacer`) (each branch keys on a unique POST field, no shadowing); i18n en/de/fr; changelog in `docs/5.8.md`.
