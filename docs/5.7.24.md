# Changelog - Version 5.7.24 (2026-10-03)

## Version Information

* Updated version from 5.7.23 to 5.7.24
* Fix: two commands sent close together can no longer both slip past a cooldown

## Bug Fixes

* **Cooldowns let near-simultaneous commands through**
  * Two viewers typing `!weather` a second apart both got a forecast, even with a 15 second cooldown set. Every built-in and custom command had the same gap: the cooldown only counted a use once the command had finished, so a second use that arrived while the first was still waiting on an API or the database passed the check too.
  * **Fix:** A use is now counted the moment the command passes its cooldown check, before any slow work starts. A second use inside the cooldown window gets the "on cooldown" reply.
  * Commands that used to check the cooldown before permissions now check permissions first, so a viewer without permission gets the permission message rather than a cooldown reply.

## Technical Details

* Every command now calls `add_usage` immediately after `check_cooldown` passes, instead of after the response is sent.
* Commands that checked the cooldown before permissions now check permissions first.
* Personal (user) custom commands check that the caller is the owner or a mod before checking the cooldown.
