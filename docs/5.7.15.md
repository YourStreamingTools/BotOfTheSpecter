# Changelog - Version 5.7.15 (2026-08-04)

## Version Information

* Updated version from 5.7.14 to 5.7.15
* Critical fix: Specter internal WebSocket reconnect and registration so weather, walkons, sound alerts, and other notices keep working after a websocket server restart

## Bug Fixes

* **Specter internal WebSocket reconnect no longer leaves the bot “half dead” after a WS server reboot**
  * The bot’s connection to the internal Specter system (`wss://websocket.botofthespecter.com`) carries overlay/alert fan-out and gates several chat features. After a websocket server restart, reconnect often failed silently or marked the bot ready before the server confirmed registration, so `!weather`, walkons, sound/video alerts, and other `websocket_notice` paths stopped working until a full bot restart.
  * **Root causes addressed:**
    * Ready state was not always gated on the server **SUCCESS** reply after **REGISTER** (some code paths treated emit as “connected”).
    * A late `disconnect` from a previous SID could clear `websocket_connected` even after a successful re-registration (race with the server’s duplicate-name cleanup).
    * Hard blocks refused weather and HTTP `/notify` fan-out whenever the Socket.IO flag was false, even though outbound notices use the HTTP `/notify` path keyed by channel API code (not the bot’s SID).
  * **Fix (in `bot.py` only for this stable ship; same pattern also in beta / v6 / Kick / Discord):**
    * Single reconnect authority: Socket.IO `reconnection=False` plus an in-process forever loop with progressive backoff (`0 → 2 → 5 → 10 → 20 → 40 → 60s`).
    * Hard timeout on `connect()` (30s) so a mid-reboot handshake cannot hang forever.
    * **REGISTER** on `connect` and again on **WELCOME**; ready only after **SUCCESS**.
    * Disconnect race: ignore `disconnect` while `client.connected` is still true; treat “duplicate session” **ERROR** carefully so a healthy new session is not torn down.
    * `is_websocket_connected()` requires both the SUCCESS flag and a live socket.
    * Weather and `websocket_notice` log a warning if mid-reconnect but still attempt HTTP API / `/notify` so overlays keep working.

## Technical Details

* Reconnect loop and handlers live entirely in `./bot/bot.py` (no shared helper module).
* Companion processes with the same critical fix in this release train: `beta.py` (documented under 5.8), `beta-v6.py` (6.0.1), `kick.py` (1.0.1), `specterdiscord.py` (6.3).
