# Changelog - Version 5.9 (UPCOMING UPDATE)

## Version Information

* Updated version from 5.8 to 5.9

## Improvements

* **Timed messages pause during a rerun**
  * While a scheduled VOD rerun is playing, timer, chat-line, and clock-time timed messages stay off so they do not flood chat.
  * They start again when that rerun finishes and the stream is still online. A bot restart during the rerun leaves them paused. Going offline still clears them as before.
  * V6 pauses its timer and chat-line timed messages the same way. V6 has no clock-time timed messages.
* **Stream Bingo called events are grouped**
  * Events called close together are sent as one chat line (split only when it would pass the message limit), instead of one line each.
  * A line waits for 6 seconds of quiet, or 20 seconds at most, and a failed send is retried twice before it is logged as dropped.
  * Other bingo messages send any waiting events first, so chat order matches the bingo feed. V6 groups them the same way.
* **Song request per-viewer limit**
  * The broadcaster, bot owner, and mods no longer count towards Max Songs Per Viewer, for both Spotify and media player requests.
  * Setting Max Songs Per Viewer to 0 makes it unlimited.
  * Media player requests are counted by Twitch user ID instead of display name, so a rename no longer resets a viewer's count. Requests made before the update are still counted by name.
  * The limit reply now shows how many songs the viewer has queued and the max, e.g. "@user you already have 2 songs in the queue (max 2). Wait for one to play, then request again."
* **Per-stream song request limit**
  * New "Max songs per viewer per stream" setting (0 = unlimited, the default) caps how many songs each viewer can request in one stream, for both Spotify and media player requests. Counts are kept by Twitch user ID and survive a bot restart mid-stream.
  * Counts reset when the stream goes live, or when a mod runs `!srreset` (everyone) or `!srreset @username` (one viewer).
  * The broadcaster, bot owner, and mods are not limited. A capped viewer is told they can ask a mod for a permit.
* **`!permitsong` skips all song request limits**
  * `!permitsong @username [count]` gives that viewer that many extra requests (1 by default). Each permit lets one request skip every song request limit: the artist limit, the per-viewer queue limit, the per-stream limit, and the same-song gap. A permit is only used once the song is actually added.
