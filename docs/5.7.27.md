# Changelog - Version 5.7.27 (2026-10-08)

## Version Information

* Updated version from 5.7.26 to 5.7.27
* Fix: stream markers follow Twitch's rules (live streams only, never during a rerun) and `!marker` explains why a marker couldn't be made

## Bug Fixes

* **Stream markers were attempted when they can't work**
  * Automatic markers (raids, cheers, subs, gift subs, follows, clips) were sent to Twitch even while the stream was offline. Twitch refused them and the bot logged an error each time.
  * During a Specter rerun, the bot would have added markers to the rerun's broadcast, which Twitch's rules don't allow.
  * **Fix:** Markers are skipped while the stream is offline or a Specter rerun is playing.

* **`!marker` gave a generic failure message**
  * When a marker couldn't be made, `!marker` only said "Failed to create a stream marker."
  * **Fix:** It now says when a rerun is playing ("Stream markers can't be added while a rerun is playing.") or when the channel doesn't save past broadcasts ("Stream markers need past broadcasts (VODs) turned on for this channel.").

* **Marker requests that timed out could crash**
  * The marker code tried to catch a timeout using a class that isn't an exception, so a network error there caused a second error instead of being handled.
  * **Fix:** Timeouts and connection errors are caught and logged.

## Technical Details

* Twitch doesn't accept stream markers when the stream isn't live, when the channel has VODs turned off, or on a rerun of a past broadcast. Specter reruns reach Twitch as normal live streams, so the bot checks `vod_reruns` in the website database for a live rerun on the channel before creating a marker. The VOD case is read from Twitch's error response.
