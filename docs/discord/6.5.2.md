# BotOfTheSpecter Discord Bot - Version 6.5.2 (2026-11-02)

## Version Information

* Updated version from 6.5.1 to 6.5.2
* Security fixes for messages the dashboard posts to Discord, for Twitch linking, for `(customapi.)`, and for unwanted `@everyone` pings

## Bug Fixes

* **Dashboard messages only post to your own server**
  * Server rules, role buttons, stream schedules and custom embeds are now only posted when the account sending them has that Discord server saved on its dashboard. Before this, a request could name any server the bot is in, post there, and replace that server's existing rules or role message.
  * If the check fails, or the database can't be reached, nothing is posted and nothing is deleted.
* **API key kept out of the logs**
  * The rules, role button, stream schedule and custom embed events no longer write the sender's API key into the Discord bot log.
* **Admin key kept out of web addresses**
  * `!linktwitch` and `!unlinktwitch` now send the admin API key in the `X-API-KEY` header to the API's `/v2` endpoints, instead of in the web address, so it stays out of access and proxy logs.
* **`(customapi.)` can no longer reach the bot's own server or private networks**
  * A custom command's `(customapi.URL)` now only fetches public internet addresses over `http` or `https`.
  * Addresses on the bot's own server (`localhost`, `127.0.0.1`, `::1`), private networks (such as `10.x`, `192.168.x`), link-local and cloud metadata addresses (such as `169.254.169.254`) are refused, along with any other address that isn't public.
  * Web names are checked after they are looked up, so a name pointing at an internal address is refused too.
  * Redirects are followed one step at a time (up to 5), and each new address is checked the same way.
  * A refused address returns `API URL not allowed` in the command's reply.
* **No more surprise `@everyone`, `@here` or role pings**
  * The bot no longer pings `@everyone`, `@here` or roles from text it passes along, such as custom command replies, `(customapi.)` responses, AI replies and song titles. The text still shows, it just doesn't ping anyone.
  * Stream alerts still ping `@everyone` or the role you picked on the dashboard, and new tickets and ticket closures still ping the support role.
  * Mentions of individual users still work everywhere.
* **A database blip no longer empties the channel cache**
  * If the database can't be read during the 5-minute channel refresh, the bot now keeps the channels it already has. Before, it replaced them with an empty list, and on the next refresh every channel looked new and a Twitch live check fired for all of them at once.
  * If the bot starts while the database is down, the first refresh that works is treated as the startup load, so it doesn't fire a check for every channel either.
  * The Time Now channel list is kept the same way when the database can't be read.
* **Music no longer freezes the rest of the bot**
  * Reading a song's length (`ffprobe`) now runs in the background. Before, the whole bot paused while it ran, so commands, alerts and other servers waited on it.
  * Each server now has its own music lock. Before, one lock was shared by every server and held during YouTube downloads, so a slow download in one server held up music everywhere.
  * The 15-minute music cache cleanup now waits while a download is running and leaves files changed in the last 10 minutes, so it can't delete a song that is still downloading.
* **One open ticket at a time**
  * Members can now only have one open ticket per server. Running `!ticket create` while one is open points them to their open ticket instead of making a new channel. Once it's closed they can open a new one.
  * Ticket admins aren't limited: the support role, anyone with Manage Server or Administrator, and the ticket system owner can open more than one.
  * Two `!ticket create` commands sent at the same moment can't both get through.
  * A ticket whose channel was deleted without being closed doesn't count, so nobody gets stuck.
* **Failures are now written to the Discord bot log**
  * About 60 places that hid errors without a trace now write a warning to the Discord bot log, naming where it happened and what went wrong. This includes database updates, live-alert lookups, voice disconnects, error replies, and message clean-up that the bot isn't allowed to do (for example, missing Manage Messages).
  * Errors that were only written at debug level, which the bot log doesn't keep, are now warnings. Most of these are on the live-alert path.
  * A message that was already deleted isn't logged, because there is nothing to fix. Expected fallbacks, such as a date that isn't in the expected format, still don't log.
* **`!play` can only play songs from the music library**
  * A song name that points outside the music folder (such as `../`, a full path, or a link to somewhere else) is now refused with "That song isn't in the music library." Before, `!play` could play any `.mp3` the bot could read on the server.
* **`!ticket issue` only changes this server's ticket**
  * The ticket is now looked up by number and server. Before, a channel named `ticket-<number>` in any server could overwrite that ticket's issue text.
  * It's refused when the ticket already belongs to another channel that still exists, and only the person who opened the ticket or a ticket admin can change the issue.
* **Only people listening can control the music**
  * `!skip`, `!stop`, changing `!volume`, `!pause`, `!resume` and `!disconnect` now need you to be in the same voice channel as the bot. Members with Move Members, Manage Server or Administrator can always control it.
  * Music commands typed in a voice channel's own chat are now recognised as the right place.
* **`!pause` pauses, and `!resume` is new**
  * `!pause` was another name for `!stop`, so it cleared the queue and left the channel. It now pauses the current song, and `!resume` (or `!unpause`) carries on.
* **One error can no longer block a channel's live alerts**
  * If handling a stream ONLINE event failed partway, that channel stayed marked as "in progress" and every later ONLINE event for it was ignored until the bot restarted. The mark is now always cleared.
* **A Twitch API error no longer counts as offline**
  * Before a stream is treated as offline, the bot asks Twitch whether it's still live. An expired token, a rate limit (429) or any other error used to let the offline through, which renamed the channel and cleared alerts while the streamer was live. Now offline only counts when Twitch confirms it; otherwise the live state is kept.
* **A bad profile time zone no longer stops event embeds**
  * An unknown time zone in a streamer's profile now falls back to UTC for the time shown on Twitch event embeds, instead of the embed never being sent.
* **`/quote` slash command registers again**
  * Slash commands were synced before the commands were loaded, so each restart removed `/quote` from Discord. They're now synced after loading.
* **AI replies are no longer paid for twice**
  * The streamed AI reply was never read correctly, so the bot made a second, non-streamed request every time. The stream is now read properly, so each reply is one request.
* **The ticket-info warning is posted once**
  * Messages in the ticket-info channel that aren't ticket commands were deleted and warned about twice. Now there's one warning.
* **User tracking "status changed" logging now works**
  * The bot now asks Discord for presence updates, so the user tracking option that logs online, idle, do-not-disturb and offline changes now fires. Before, it never did.
  * User tracking settings for status changes are cached for up to a minute, so the frequent status updates don't each hit the database.
  * **Before deploying:** turn on **Presence Intent** for the bot under **Bot → Privileged Gateway Intents** in the Discord Developer Portal. Without it, Discord refuses the connection and the bot won't start; the bot log says so if that happens.
* **Custom commands work for streamers whose display name differs from their login**
  * Custom commands now look up the streamer's commands by username, like the rest of the bot. Before, the display name was used, so streamers with a different display name (non-Latin names, for example) got no custom commands in Discord.

## Technical Details

* Changes are in `./bot/specterdiscord.py`.
